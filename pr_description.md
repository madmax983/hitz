* 🦠 Threat: Two memory exhaustion vulnerabilities (Denial of Service) were discovered. First, unbounded descriptor lengths provided by the guest OS could cause `resize` to allocate massive zero-filled buffers during IO failures in `virtio/net.rs` and `virtio/vsock.rs`. Second, HTTP request bodies in `router.rs` were collected without size limits via `req.into_body().collect()`.
* 🛡️ Defense: Hardened interfaces by replacing `.resize()` with `.reserve()` and a bounded temporary buffer in Virtio operations. Enforced a hard 64KB cap on incoming HTTP payloads using `http_body_util::Limited::new` prior to collection.
* 💥 Severity: Critical - Unauthenticated or unprivileged guests could trigger out-of-memory panics, crashing the daemon or host processes.
* 🧪 Verification: Verified memory safety manually. Tests pass successfully via `cargo test -p hitz-daemon`.
